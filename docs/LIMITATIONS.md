# Evidence boundaries and limitations

- The public demo and regression tests use synthetic motion. They validate engineering behavior, not VSL accuracy, educational improvement, linguistic equivalence or calibration for real learners.
- This release uses 2D coordinate geometry, without the legacy application's 60/40 coordinate/angular blend or learned classifier. Non-manual features, face, depth, semantic equivalence and natural signer variation are not assessed. Fine handshape errors can evade this score.
- A bank assembled from existing video still requires confirmed labels, representative reference selection, identity/acquisition metadata and rights. Adding many references can increase false matches. A cap on tolerances and coherent selection reduce particular engineering failure modes but do not prove general robustness.
- Quality and score thresholds are configurable heuristics. A separate, representative calibration set and independent evaluation are necessary for meaningful operating-point claims. User-declared signer IDs are not independently verified.
- Exact byte/canonical-pose overlap detection cannot identify all perceptual duplicates, overlapping clips or falsely declared source groups. Hashes provide consistency checks, not authentication.
- Shoulder-based normalization does not remove camera viewpoint, articulation differences, occlusion, perspective or mirror ambiguity. Repeated time samples after DTW can change weighting; path-length and tolerance choices need sensitivity analysis on authorized real data.
- Video timing is frame-index/FPS based and assumes constant frame rate. No variable-frame-rate timing claim is made. MediaPipe hand confidence is a binary detection-presence indicator. The pinned legacy Holistic adapter is optional and needs a supported platform wheel; it is not verified on Jetson Nano.
- Each upload should contain one deliberately trimmed attempt. The software does not choose the best subsequence from repeated attempts, which could inflate assessment.
- The server is a small local demo, with no authentication, distributed queue or production-service hardening. Uploaded clips are temporary on the server host. This is not a browser-only or camera-never-leaves-device architecture. Use operator-controlled access and separate service controls if deploying beyond loopback.
- The extraction library and bundled model components retain their own licensing/notice obligations. MIT licensing of this toolkit does not grant rights over user data or imported reference assets.

The strongest next evidence is an authorized, independently held-out real pose/video use case with source/signer declarations, positive and confusable-negative pairs, extraction-quality coverage, false-match/false-reject rates and reviewer-inspectable receipts. Human-rated learner performances are required before claiming useful proficiency grading or pedagogical benefit. No competitor accuracy superiority is established by this release.
