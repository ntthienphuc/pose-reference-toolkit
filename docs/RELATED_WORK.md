# Related work and positioning

Targeted review, updated 2026-10-11. This is not an exhaustive novelty search. Code features below are based on the linked repositories/papers, not reproduced competitor benchmarks. No source from these projects is vendored or copied into this toolkit. Entries carried forward from the 2026-10-06 review are identified separately from sources inspected during this update.

| Work | Relevant overlap | Pose Reference's proposed emphasis |
|---|---|---|
| [MediaPipe–DTW sign recognition](https://github.com/gabguerin/Sign-Language-Recognition--MediaPipe-DTW) | Imports reference videos, extracts hand-angle features, applies DTW and voting. `yt_download.py` automatically obtains/cuts source clips. | Audited, explicitly permission-declared bank construction; role separation; complete-exemplar feedback receipts; recapture versus similarity outcomes. Existing-video reference import is **not** a new idea. |
| [pose-evaluation](https://github.com/sign-language-processing/pose-evaluation), [Jiang et al., WMT 2025](https://aclanthology.org/2025.wmt-1.4/) | Reusable sign-pose metrics, DTW processing, missing-keypoint handling and varying pose lengths/formats; paper evaluates retrieval and human correlation. | Bank lifecycle plus target-practice decision/visualization tied to one selected exemplar. Do not claim pose comparison or missing-data processing is original, or equal human-validation evidence. |
| [SignBridge](https://github.com/mhmdtaha091/SignBridge) | Existing-video reference import, MediaPipe hand/pose features, DTW medoid selection, multivariate DTW with a warp path and browser feedback on hand height, finger spread and pace. | Inspectable bank lifecycle, partition controls, quality decisions and complete-exemplar comparisons through an independent Python API/CLI. Existing-video bank construction and DTW feedback are already implemented here; a different interface alone does not establish a scientific contribution. |
| [Akamine et al., 2026](https://doi.org/10.3758/s13428-026-02975-5), [dtw_validation](https://github.com/ShoAkamine/dtw_validation) | MediaPipe preprocessing, body-relative and wrist-relative normalization, open-begin/end DTW, handedness/mirroring policies and human validation across two corpora. | A reusable bank and assessment workflow with explicit admissibility and provenance. DTW distance must remain a geometric measure; the paper's weak-to-moderate human association does not establish calibrated linguistic correctness. |
| [Learn2Sign, 2019](https://ceur-ws.org/Vol-2327/IUI19WS-ExSS2019-13.pdf) | Modular feedback on sign location, movement and handshape; waterfall feedback architecture; real learner evaluation. | Software reuse and inspectable comparison evidence. Automated or component-specific sign-practice feedback itself is established prior art. |
| [Holzknecht et al., 2024](https://doi.org/10.1080/15434303.2024.2364877) | Automated vocabulary assessment, handshape/movement feedback; compares machine and human ratings and studies learners' perceptions. | A transparent geometric software component with explicitly limited evidence. Human-rated validity and learning outcomes remain future work. |
| [Wen and Xu, 2024 preprint](https://arxiv.org/abs/2404.10383) | Two-stage sign-performance scoring with reconstruction, rotation and smoothing. | The contribution here is reference-artifact construction and engineering contracts, not a new learned scoring algorithm. |

## Close implementation comparison

SignBridge's [reference exporter](https://github.com/mhmdtaha091/SignBridge/blob/22000aae3e0cf9836178bd3c409a047b08f24d70/ml/export_lesson_references.py) reads existing WLASL clips, extracts usable sequences and selects a DTW medoid. Its [DTW implementation](https://github.com/mhmdtaha091/SignBridge/blob/22000aae3e0cf9836178bd3c409a047b08f24d70/web/src/recognition/dtw.ts) returns an alignment path. Its [feedback module](https://github.com/mhmdtaha091/SignBridge/blob/22000aae3e0cf9836178bd3c409a047b08f24d70/web/src/recognition/feedback.ts) uses whole-sequence averages for component feedback rather than that path. These source files were inspected; the application and its reported recognition benchmarks were not rerun. No associated accepted paper was verified. Alignment-localized evidence and reference-policy sensitivity are useful comparison questions, not established advantages of this toolkit.

Akamine et al.'s full article and [DTW code](https://github.com/ShoAkamine/dtw_validation/blob/0b439f47e47b8b807fd219ecac477e0868cc2cf3/kinematics/study2/scripts/dtw_functions.py) were inspected. The repository includes Python/R scripts and processed anonymized data, and directs users to OSF for motion traces. No root license file was present in the inspected tree; do not infer permission to copy code or redistribute data from public access. Learn2Sign's full workshop paper was inspected, including its per-sign evaluation and learner-data description; a reproducible code release was not verified.

## Defensible contribution statement

“Pose Reference Toolkit provides an auditable workflow for constructing pose reference banks from authorized sources and producing quality-aware, complete-exemplar geometric feedback for isolated practice attempts. Source roles, pose contracts, bank assets, decision policies and selected alignment are exposed as inspectable artifacts through a reusable Python API, CLI and web adapter.”

Do not describe the software as the first automatic sign tutor, the first reference-video scorer, a novel DTW algorithm, or a validated substitute for sign-language instructors. The useful distinction is the combination of bank construction, coherent comparison and verifiable outcomes in a reusable release; whether that is sufficiently original for a journal is an editorial/reviewer judgment.

## SoftwareX precedents and evidence scope

These are software-publication precedents, not sign-language performance baselines. Accepted examples do not guarantee acceptance of this toolkit.

**EmbedKD** ([paper](https://doi.org/10.1016/j.softx.2026.103029), [version v0.1.5](https://github.com/hublinhdn/embedkd/tree/v0.1.5), MIT): the supplied full paper, repository tree and export code were inspected. It packages a reproducible metric-distillation lifecycle using established objectives. Reported evidence includes real-data retrieval comparisons, multi-seed objective results, teacher-quality sensitivity, cross-domain losses, export parity and timed CPU deployment. Its use here is a standard for connecting software capabilities to empirical outcomes; a passing unit-test suite alone is not equivalent evidence.

**MotionPerfection** ([paper](https://doi.org/10.1016/j.softx.2022.101247), [journal archive](https://github.com/ElsevierSoftwareX/SOFTX-D-22-00126)): the archived implementation/README was inspected at `8f4a4c74d7afc928adb0fcad3ca9918cb66cc056`. It reuses reference-video frames, synchronizes participant videos and generates expert-assessment forms. Full-text access failed during this update, so its quantitative result tables were not audited. This demonstrates a related assessment workflow, not automated scoring equivalence.

**PyBodyTrack** ([paper](https://doi.org/10.1016/j.softx.2025.102272), [repository](https://github.com/bihut/PyBodyTrack), Apache-2.0): source inspected at `99d5b9791ec755abd72a29ecc02cfb2ed6100bfc`. It supports selectable pose estimators/body regions, filtering and mathematical movement measures. Full-text download failed; no numerical comparison with its paper is claimed. It is an example of a reusable motion-analysis library based on existing components.
